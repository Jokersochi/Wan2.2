## 2024-04-19 - unpatchify loop overhead
**Learning:** In Python/PyTorch high-frequency code paths like the 'unpatchify' loop, replacing generalized functional constructs like `math.prod` and list comprehensions with `zip` with direct tuple unpacking and scalar multiplication (e.g., `v[0] * v[1] * v[2]`) reduces execution overhead significantly.
**Action:** Replace `math.prod(v)` and `[i * j for i, j in zip(v, self.patch_size)]` with explicit unpacks like `v[0] * v[1] * v[2]` and direct multiplication elements `v[0] * self.patch_size[0]`, etc.
## 2024-11-06 - Optimize Tensor splitting with unbind vs chunk+squeeze
**Learning:** PyTorch's `.chunk(N, dim=D)` combined with `.squeeze(D)` involves intermediate tensor allocations and multiple operations in Python. Replacing it with `.unbind(dim=D)` directly drops the dimension and returns a tuple, saving processing overhead on critical, highly-repeated attention paths. However, when `.chunk()` is used *without* an explicit `.squeeze()` (e.g. `Head_S2V` and `model_animate`), it serves to preserve a size-1 dimension for broadcasting. In those cases, replacing with `.unbind()` would cause dimensionality mismatches and break broadcasting.
**Action:** Replace `.chunk()` with `.unbind()` only when explicitly followed by `.squeeze()` on the chunked dimension, to safely speed up code without risking downstream shape regressions.
