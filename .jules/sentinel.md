## 2025-02-28 - [Sentinel] Fixed insecure assert usage in DashScopePromptExpander
**Vulnerability:** The code used `assert` statements to validate HTTP response status codes and task parameters. When Python is executed with the `-O` optimization flag, these statements are ignored, potentially bypassing crucial logic or error handling for external API interactions.
**Learning:** External API validation should always use explicit control flow and exceptions to guarantee reliable error state execution.
**Prevention:** Use explicit `if` statements coupled with context-appropriate standard exceptions (like `ValueError` or `RuntimeError`) instead of `assert` to handle validation in production code environments.
## 2025-02-18 - Fix Insecure Temporary File Leak (CWE-459) in Prompt Expander
**Vulnerability:** In `wan/utils/prompt_extend.py`, a temporary image file was created using `tempfile.NamedTemporaryFile(delete=False)`. While the code attempted to manually remove the file via `os.remove(fname)` at the end of the function, this removal could be bypassed if an exception occurred earlier in the function logic, leading to a file leak and resource exhaustion over time (CWE-459).
**Learning:** Manual cleanup of resources without a `try...finally` block is unsafe in exception-prone execution paths. `NamedTemporaryFile(delete=False)` is often misused when external paths are needed; using `tempfile.mkstemp` and explicitly closing the file descriptor is the safer pattern for external libraries.
**Prevention:** Always wrap temporary file operations that require manual cleanup in a `try...finally` block where the cleanup occurs in the `finally` clause. When passing temporary files to external APIs, prefer `tempfile.mkstemp()` combined with `os.close()` rather than `NamedTemporaryFile`.
